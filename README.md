# 网络音频权利与多形态分发账本

管理网络音频素材授权、多形态版本、发布门禁和收入结算。

## 参与方与事实

主要参与方包括音频创作者、节目编辑、嘉宾及权利人、法务人员、商务运营人员、平台运营人员。领域资料记录以下已经确认的事实：

- 网络音频覆盖有声书、广播剧、播客和视频播客等多种内容形态
- 行业正在形成一次录制、多形态分发的生产方式
- AI 配音、声音克隆、版权归属和合成内容标识带来新的治理需求
- 同一次访谈会被剪成完整音频、视频播客、付费专辑和跨平台切片等多种成品
- 选题立项阶段即记录参与者、原始录制、文字稿和素材来源
- 声音与肖像同意、音乐许可各自带有用途、地域和期限限制
- 每个成品版本发布时冻结所引用的素材与权利水位
- 修改一处片段时需要能列出受影响的已发布形态及其处置方式
- 广告分成、会员收入、IP 授权和线下活动收入按各自合同归集
- 退款、撤单和后补版权费以冲正方式落账
- 平台可能重发结算回执，分账需要可安全续做且不重复付款
- 嘉宾撤回未来使用授权不抹去此前合法发布的责任记录
- 权利人可以核对自己的许可曾在哪些内容中被使用

## 业务约束

- 素材授权范围
- 成品版本水位
- 合成内容标识
- 收入分成
- 撤回与下架
- 商业秘密裁剪
- 角色信息隔离
- 许可解释专责
- 发布前授权门禁
- 分账幂等续做
- 历史责任记录保留

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/audio_context.py` 负责读取和校验这些资料。`docs/asset-service.md` 描述内容资产服务的实体、生命周期与不变式。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
